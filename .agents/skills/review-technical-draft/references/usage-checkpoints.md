# 사용법 원고에서 반복 확인할 항목

라이브러리·API 사용법 원고를 리뷰할 때 쓰는 검토 단서다. 목록 자체를 근거로 인용하거나, 모든 항목을 매번 지적하지 않는다. 원고의 기준 버전·자료형·코드에서 관련 있는 경우만 확인한다.

특정 라이브러리 원고를 여러 편 리뷰하며 반복되는 단서가 쌓이면 `references/<라이브러리>-checkpoints.md`로 따로 만들고, SKILL.md의 "대상과 맥락 파악"에 그 원고일 때만 읽도록 한 줄을 추가한다.

## 버전과 환경

- 기본값, 자료형 추론, 반환형은 버전·백엔드·설정에 따라 달라질 수 있다. 저장된 실행 환경과 본문의 기준 버전을 대조한다.
- 출력에 보이는 클래스 이름이나 자료형을 모든 입력에 대한 규칙으로 단정하지 않았는지 본다.
- 사용 중단 예고(deprecated)나 동작 변경이 있는 기능은 기준 버전의 공식 문서·변경 기록을 확인한다.

## 반환값과 원본 변경

- 반환된 결과를 표시하기만 했는지 변수에 저장했는지 확인한다. 원본을 변경하지 않고 새 객체를 반환하는 호출은, 결과를 저장하지 않았다면 원본이 바뀌었다고 서술하지 않는다. 원본을 직접 바꾸는 호출(`items.append(2)`, `items.sort()` 등)은 저장하지 않아도 원본이 바뀐다.
- 원본을 바꾸는 호출과 새 객체를 돌려주는 호출을 구분한다. '원본' 대신 실제 변수 이름으로 영향 범위를 설명할 수 있는지 본다.
- 복사와 참조(뷰)의 구분이 버전이나 설정에 따라 달라지면 기준 버전을 확인한다.

## 이름, 위치, 경계

- 이름(키·라벨)으로 찾는 방식과 위치(순서)로 찾는 방식을 구분한다. 정렬·필터링·삭제 뒤에 남는 이름과 위치를 출력과 대조한다.
- 범위 지정에서 끝 경계를 포함하는지, 범위를 넘을 때 오류가 나는지 잘라 내는지는 함수마다 다르다. 한 함수의 동작을 비슷한 함수까지 넓히지 않는다.
- 단일 값 조회와 목록 조회, 범위 조회는 없는 키나 범위 초과를 처리하는 방식이 다를 수 있다.
- 문자열 검색은 일반 문자열 검색과 정규식 검색을 구분한다.
- Markdown 표 안의 `|`는 코드 안에서도 이스케이프한다.

## 계산과 대응

- 두 객체를 계산하거나 대입할 때 이름(키)으로 맞추는지 순서로 맞추는지 확인한다.
- 비슷한 이름의 함수(값 대응과 함수 적용 등)가 받는 입력과 결과를 구분한다. 한 사용 예가 같다고 두 함수 전체가 같다고 확대하지 않는다.
- 정렬에서 같은 값의 순서, 빈 값의 위치는 옵션과 안정 정렬 여부를 확인한다. 동률의 순서가 달라졌다고 출력 오류로 단정하지 않는다.

## 빈 값과 결과 해석

- 라이브러리가 빈 값으로 인식하는 것과 빈 문자열·공백·0을 구분한다.
- 집계·개수·비율이 빈 값을 빼는지 포함하는지 확인한다. 같은 대상에서도 '행 수'와 '값 수'가 다를 수 있고, 비율의 분모가 무엇인지 본다.
- 그룹 전체가 비어 있으면 그 그룹의 집계 결과도 비어 있을 수 있다. 그 결과로 빈 값을 채워도 채워지지 않는 경우를 확인한다.
- 여러 개의 답이 나올 수 있는 함수(최빈값 등)나 빈 결과는, 범용 처리법을 설명하는 자리에서만 보완한다. 현재 예제에 값이 있으면 실행 오류라고 하지 않는다.
- API 사용법의 시연을 분석 판단의 권고로 확대하지 않는다. 비율이나 평균 차이만으로 삭제·대체의 적절성이나 인과를 단정하지 않는다.

## 참고할 문서

필요한 동작의 문서만 열고 기준 버전과 맞는지 확인한다. 우선순위는 해당 버전의 공식 API 문서, 사용자 가이드, 변경 기록(릴리스 노트·마이그레이션 안내), 소스 코드 순이다.
