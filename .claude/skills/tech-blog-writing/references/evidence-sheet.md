# 증거 시트와 작성 노트

## 증거 시트

CP1에서 채워 `drafts/<slug>/00-plan.md`에 넣는 작업 메모다. 글에 그대로 싣지 않는다.
각 항목에 **출처**를 적는다: `사용자 제공` / `세션 실행` / `외부 문서(URL, 확인 날짜)` / `없음`.

```markdown
## 증거 시트: <글 가제>
- 유형: T / 분야: INF
- 기준일: YYYY-MM-DD

### 환경 (P3)
| 항목 | 값 | 출처 |
|---|---|---|
| kubernetes | v1.xx.x | 사용자 제공 (kubectl version 출력) |
| CNI | ? | 없음 → 요청 |

### 관측과 출력 (P1, P8)
- [E1] 증상 로그: ```...``` (사용자 제공)
- [E2] 수정 후 같은 요청의 출력: 없음 → 요청

### 수치 (P6)
| 값 | 의미 | 종류 | 조건 | 출처 |
|---|---|---|---|---|
| 1,240ms | p99 지연 | 직접 측정 | 동시성 50, 5회 중앙값 | 사용자 제공 |

종류: 직접 측정 / 인용 / 환산 / 추정

### 가설 기록 (P4)
| 가설 | 결과 | 근거 |
|---|---|---|
| DNS 지연 | 기각 | E3: 직접 IP로도 재현 |

### 외부 근거 (P7)
- 이슈·PR, 공식 문서, 논문: 링크와 확인 날짜
- 링크는 HTTP 200만 보고 확인을 끝내지 않는다. 옮겨진 페이지가 200과 함께 이동 안내(meta refresh)만 돌려줄 수 있다. 받은 페이지의 제목과 문서 버전, 걸려는 절의 앵커 id가 있는지 보고, 옮겨졌으면 새 주소로 건다

### 비어 있는 필수 항목
- CNI 버전, 수정 후 재검증 출력 → 사용자에게 요청함 (YYYY-MM-DD)
```

**필수 항목 기준:** 주 유형 체크리스트와 분야 체크리스트에서 해당하는 항목. 특히 다음은 유형별로 반드시 확인한다.

| 유형 | 반드시 확인 |
|---|---|
| T | 증상 원문, 환경 버전, 원인을 확인한 방법, 수정 후 재검증 결과 |
| H | 환경 버전, 대조군, 반복 횟수, 원시 출력 |
| G | 각 핵심 명령의 실제 출력, 도구 버전 |
| C | 1차 근거(명세, 소스, 공식 문서) |
| R | 원문 서지 정보, 원문의 한계 |
| E | 기간, 규모, 필자 역할 |
| A | 상대 주장 원문 링크, 반례 코드나 데이터 |

## 작성 노트

글 끝에 작성 노트나 AI 고지를 두지 않는다. 독자에게 어색하게 읽히기 때문이다.

- 확인하지 못한 주장은 작성 노트가 아니라 **그 주장이 있는 본문 자리**에 표시한다(P2: "확인하지 못했다", "추정").
- 실행 환경(버전)과 출력의 출처(첨부 노트북)는 본문에 쓰지 않고 프런트매터 `env`·`notebook`에 적는다. 레이아웃이 제목 아래 버전 꼬리표와 노트북 카드로 보여 준다.
- 대표 이미지 출처는 라이선스가 표기를 요구할 때만 본문 끝에 한 줄 둔다. 요구하지 않으면 `status.md`에만 기록한다.
- 사용자가 작성 노트나 AI 고지를 요청하면 넣는다. 그때도 제품명·모델명은 적지 않는다.
- 이미 게시한 글에 있는 작성 노트는 그대로 둔다.
